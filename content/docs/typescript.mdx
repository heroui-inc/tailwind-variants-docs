Tailwind Variants is written in TypeScript. Variant keys and values infer automatically — no code generation required.

## `VariantProps`

Extract the props a recipe accepts:

```tsx
import { tv, type VariantProps } from 'tailwind-variants';

export const button = tv({
  base: 'inline-flex cursor-pointer items-center justify-center rounded-full px-4 py-1.5 font-medium select-none',
  variants: {
    variant: {
      primary: 'bg-zinc-900 text-white',
      secondary: 'bg-zinc-100 text-zinc-900',
      tertiary: 'text-zinc-600'
    },
    flat: {
      true: 'bg-transparent shadow-none'
    }
  },
  defaultVariants: {
    variant: 'primary'
  }
});

type ButtonVariants = VariantProps<typeof button>;
// variant?: "primary" | "secondary" | "tertiary"
// flat?: boolean

interface ButtonProps extends ButtonVariants {
  children: React.ReactNode;
  className?: string;
}

export function Button({ children, className, ...variants }: ButtonProps) {
  return (
    <button className={button({ ...variants, className })}>
      {children}
    </button>
  );
}
```

Keys with `defaultVariants` become optional on the type.

## Numeric keys

Options keyed by numbers, such as spacing scales, stay number literals on the type:

```ts
const box = tv({
  variants: {
    gap: { px: 'gap-px', 0: 'gap-0', 2: 'gap-2' },
  },
});

type BoxVariants = VariantProps<typeof box>;
// gap?: "px" | 0 | 2

box({ gap: 2 }); // "gap-2"
```

Pass them as numbers. String forms such as `"2"` are not part of the type.

## Required variants

TV does not have a built-in "required variant" flag. Use TypeScript utilities:

```ts
type ButtonVariants = VariantProps<typeof button>;

type RequiredSize = Omit<ButtonVariants, 'size'> &
  Required<Pick<ButtonVariants, 'size'>>;
```

Or model the axis without a default so TypeScript keeps it required.

## Stricter validation

Unknown or misspelled keys in `variants`, `compoundVariants`, and `defaultVariants` fail at compile time, as do unknown slot names in slot-shaped class values. Nothing gets silently ignored:

```ts
const button = tv({
  variants: { size: { sm: 'text-sm' } },
  // ✗ compile error — 'colour' is not a variant key
  defaultVariants: { colour: 'primary' }
});
```

If an upgrade surfaces new type errors here, they almost always point at real typos. See [Migration](/docs/migration#to-v400).

## Slotted return types

Slotted recipes return an object of slot functions. Destructure once for cleaner types:

```ts
const alert = tv({
  slots: {
    base: 'flex gap-3 rounded-lg p-4',
    title: 'font-semibold',
    description: 'text-sm'
  },
  variants: {
    color: {
      default: {
        base: 'bg-zinc-100',
        title: 'text-zinc-900'
      },
      danger: {
        base: 'bg-red-50',
        title: 'text-red-900'
      }
    }
  }
});

type AlertSlots = ReturnType<typeof alert>;
// AlertSlots.base, .title, .description — each (props?) => string

function Alert({ color }: VariantProps<typeof alert>) {
  const { base, title, description } = alert({ color });

  return (
    <div className={base()}>
      <p className={title()}>Title</p>
      <p className={description()}>Body</p>
    </div>
  );
}
```

## Defining variants apart from `tv()`

Keep options in their own file (a theme, a shared preset) with `defineVariants`. It checks them where they are written and keeps the literal types `tv()` needs. A plain object widens `compoundVariants` and `defaultVariants` values to `string`, which `tv()` rejects.

```ts
// button.theme.ts
import { defineVariants } from 'tailwind-variants';

export const buttonTheme = defineVariants({
  base: 'inline-flex items-center rounded-md',
  variants: {
    size: { sm: 'h-8 px-3 text-sm', lg: 'h-12 px-6 text-lg' },
    disabled: { true: 'opacity-50' }
  },
  compoundVariants: [{ size: 'lg', disabled: true, class: 'cursor-not-allowed' }],
  defaultVariants: { size: 'sm' }
});
```

```ts
// button.ts
import { tv, type VariantProps } from 'tailwind-variants';
import { buttonTheme } from './button.theme';

export const button = tv(buttonTheme);
export type ButtonProps = VariantProps<typeof buttonTheme>; // same as VariantProps<typeof button>

// Override a field, keep the rest:
export const largeButton = tv({ ...buttonTheme, defaultVariants: { size: 'lg' } });
```

`defineVariants` returns its argument unchanged, so it has no runtime cost. It is exported from the main, `/lite`, and `/config` entries.

## `as const` for external definitions

`as const` is the zero-runtime alternative without a helper. `tv()` accepts the object, but mistakes are only reported at the `tv()` call, not where the options are written, and `VariantProps` needs the `tv()` result instead of the object.

When variants live outside `tv`, use `as const` so TypeScript preserves literal keys:

```ts
const variants = {
  primary: 'bg-zinc-900 text-white',
  secondary: 'bg-zinc-100 text-zinc-900',
  tertiary: 'text-zinc-600'
} as const;

const button = tv({
  variants: { variant: variants }
});
```
