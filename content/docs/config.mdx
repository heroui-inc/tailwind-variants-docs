# Config

Tailwind Variants has several ways to specify config options:

1. Passing config to the `tv` function
1. Creating a custom `tv` instance using `createTV`
1. Modifying the `defaultConfig` variable

## Build Options (v3+)

Starting from v3, Tailwind Variants offers two build options:

### Default Build

- Import from `tailwind-variants`
- Includes conflict resolution
- Supports all configuration options including `twMerge` and `twMergeConfig`

```ts
import { tv, createTV, cn, cnMerge, cx } from 'tailwind-variants';
```

### Lite Build

- Import from `tailwind-variants/lite`
- No conflict resolution for a smaller bundle (~80% smaller)
- **Does not support** `twMerge` or `twMergeConfig` options
- Does **not** export `cnMerge`

```ts
import { tv, createTV, cn, cx } from 'tailwind-variants/lite';
```

Choose the lite build if:

- You don't need automatic Tailwind class conflict resolution
- Bundle size is a critical concern
- You handle class merging manually or don't have conflicting classes

For more on conflict resolution, see the [Conflict Resolution](/docs/conflict-resolution) page.

### Local Config

The easiest way to configure Tailwind Variants is using the second argument of
the `tv` function. This will set the configuration for this specific `tv` call
and is useful for one-off config changes.

```ts
tv(
  { base: '' },
  {
    twMerge: false
    // ...
  }
);
```

### Global config

If you want your config to apply to all usages of `tv`, you can modify the
`defaultConfig` variable to set global configuration for all calls of `tv`.

Starting from v3.2.0, `defaultConfig` is exported as a value (not just a type), allowing you to import and modify it directly:

```ts
import { defaultConfig } from 'tailwind-variants';

defaultConfig.twMerge = false;
```

> **Note**: In v3.2.0+, `defaultConfig` is exported as an actual value, making it easier to modify global configuration. This works in both the default and lite builds (lite ignores merge-related options).

### Custom `tv` instance

If you have different configs for different use cases, the default config might
not work for you. Instead, you can use the `createTV` function to create an
instance of `tv` with the specified config.

```ts
import { createTV } from 'tailwind-variants';

const tv = createTV({
  twMerge: false
  // ...
});

tv({ base: '' });
```

### Advanced: Custom `tv` wrapper

For more advanced use cases, you can create a custom `tv` wrapper that extends the default configuration with your own custom merge config. Prefer `{ extend, override }` — legacy flat `theme` / `classGroups` fields are still accepted and normalized into `extend`:

```ts
// tv.ts
import type { TV, TWMergeConfig } from 'tailwind-variants';
import { tv as tvBase } from 'tailwind-variants';

const COMMON_UNITS = ['small', 'medium', 'large'];

const twMergeConfig = {
  extend: {
    theme: {
      spacing: ['divider'],
      radius: COMMON_UNITS
    },
    classGroups: {
      shadow: [{ shadow: COMMON_UNITS }],
      opacity: [{ opacity: ['disabled'] }],
      'font-size': [{ text: ['tiny', ...COMMON_UNITS] }],
      'border-w': [{ border: COMMON_UNITS }],
      'bg-image': [
        'bg-stripe-gradient-default',
        'bg-stripe-gradient-primary',
        'bg-stripe-gradient-secondary',
        'bg-stripe-gradient-success',
        'bg-stripe-gradient-warning',
        'bg-stripe-gradient-danger'
      ]
    }
  }
} satisfies TWMergeConfig;

export const tv: TV = (options, config) =>
  tvBase(options, {
    ...config,
    twMerge: config?.twMerge ?? true,
    twMergeConfig: {
      ...config?.twMergeConfig,
      ...twMergeConfig,
      extend: {
        ...config?.twMergeConfig?.extend,
        ...twMergeConfig.extend,
        theme: {
          ...config?.twMergeConfig?.extend?.theme,
          ...twMergeConfig.extend.theme
        },
        classGroups: {
          ...config?.twMergeConfig?.extend?.classGroups,
          ...twMergeConfig.extend.classGroups
        }
      }
    }
  });
```

This approach allows you to:

- Extend the conflict resolution config with custom theme values
- Add custom class groups for your design system
- Maintain type safety with the `TV` type
- Override any default configuration while preserving the rest

## Config Options

```ts
type TWMConfig = {
  twMerge?: boolean;
  twMergeConfig?: TWMergeConfig;
};
```

### `twMerge`

**description:** Whether to merge conflicting Tailwind classes.
It avoids having duplicate Tailwind classes. (Recommended) See more in [Conflict Resolution](/docs/conflict-resolution).

> **Note:**
>
> - Starting from v3.3.0, conflict resolution is included in the default build. You no longer need to install `tailwind-merge` for Tailwind Variants.
> - This option is **only available in the default build** (`tailwind-variants`), not in the lite build (`tailwind-variants/lite`).

**type:** `boolean`

**default**: `true` (default build only)

**availability**: Default build only (`tailwind-variants`)

### `twMergeConfig`

**description:** Config object for conflict resolution. Prefer `{ extend, override }`. Compatible with common `tailwind-merge` v3 config shapes so existing configs can be reused. See [Conflict Resolution](/docs/conflict-resolution).

**type:** `TWMergeConfig`

**default**: `{}`

**availability**: Default build only (`tailwind-variants`)
