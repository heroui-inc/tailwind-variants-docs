Responsive styles are plain Tailwind. Put breakpoint prefixes like `sm:`, `md:`, and `lg:` directly in your `base`, variant, and slot class strings — there is no TV-specific responsive API.

See [Tailwind responsive design](https://tailwindcss.com/docs/responsive-design) for breakpoint syntax.

<Callout type="info">
  The old `responsiveVariants` option was removed. It depended on Tailwind's `content.transform`, which [Tailwind CSS v4](/docs/tailwind-v4) no longer supports. Prefixes in class strings replace it.
</Callout>

## At the call site

Overrides accept responsive classes too:

```ts
button({
  variant: 'primary',
  class: 'w-full sm:w-auto'
});
```

## Conflict resolution

Responsive utilities are distinct classes (`text-sm` vs `sm:text-base`). The default build merges conflicts **within the same breakpoint**, like `sm:px-2` vs `sm:px-4`, the same way it merges unprefixed utilities. See [Class resolution](/docs/class-resolution).
