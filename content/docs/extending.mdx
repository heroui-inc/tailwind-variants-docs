`extend` merges one or more recipes into another. Start from a base button, then add icon-only sizing or new variant tokens without copying the whole definition.

## Merge behavior

`extend` deep-merges:

- **base** — concatenated
- **slots** — merged by key
- **variants** — merged by axis; new keys add axes, existing keys add values
- **defaultVariants** — child overrides parent for matching keys
- **compoundVariants** — arrays concatenated
- **compoundSlots** — arrays concatenated

The returned object exposes merged metadata: `variants`, `variantKeys`, `defaultVariants`, and slot keys reflect the full composed recipe.

Plain and slotted recipes compose cleanly. When one side of a merge is a plain class string and the other is a per-slot object, the string folds into the `base` slot:

```ts
import { tv } from 'tailwind-variants';

const plain = tv({
  base: 'p-1',
  variants: { size: { sm: 'text-sm' } }
});

const slotted = tv({
  extend: plain,
  slots: { icon: 'size-4' },
  variants: { size: { sm: { icon: 'size-3' } } }
});

const { base, icon } = slotted({ size: 'sm' });
base(); // => "p-1 text-sm"  — the parent's string lands on base
icon(); // => "size-4 size-3"
```

## Extending slotted recipes

Slots merge by key. Child recipes can add slots or override styles on inherited ones:

```ts
import { tv } from 'tailwind-variants';

const card = tv({
  slots: {
    base: 'rounded-xl border p-4',
    title: 'text-sm font-medium',
    description: 'text-sm text-zinc-500'
  }
});

const mediaCard = tv({
  extend: card,
  slots: {
    media: 'mb-3 aspect-video rounded-lg bg-zinc-100',
    title: 'text-base font-semibold'
  }
});

const { base, media, title, description } = mediaCard();
```

`mediaCard` keeps `base` / `description` from `card`, adds `media`, and tightens `title`.

## Multiple parents

Pass a non-empty array to compose several recipes at once (v3.4+). Parents merge left to right, and the child's own options are applied last:

```ts
const button = tv({
  extend: [baseButton, focusRing, pressable],
  base: 'gap-2' // applied after every parent
});
```

Merging happens once at definition time, so composing multiple parents does not slow down invocations.

A common real-world use is sharing cross-cutting concerns — focus rings, press feedback, disabled states — as small recipes and composing them into interactive components. Try tabbing to and pressing the buttons below:

When parents overlap, the usual merge rules apply in array order: later parents win for `defaultVariants`, and conflicting classes resolve in favor of the last contributor. If two recipes share a variant axis that should stay independent, keep them separate and join their output with [`cx` / `cn`](/docs/class-resolution) instead.

Before v3.4, chain extends to combine multiple bases:

```ts
const extended = tv({ extend: baseButton });
const final = tv({ extend: extended /* ... */ });
```
